# ZenPulse: AI Meditation App

[English version](./README.md)

Тестовое задание на React Native + Expo: мобильный прототип meditation-приложения с paywall, карточками медитаций и AI-аффирмациями по выбранному настроению.

## Обзор

В приложении реализованы 3 экрана:

- `Paywall`: выбор доступа с вариантами `Free`, `Monthly` и `Yearly`
- `Meditations`: список сессий с изображениями, длительностью и блокировкой premium-контента
- `AI Mood`: выбор настроения и генерация аффирмации

## Что реализовано

- Премиальный paywall в meditation-стиле с визуально выделенным годовым тарифом
- Бесплатный режим с ограниченным доступом к медитациям
- Premium-режим, открывающий все карточки медитаций
- 6 карточек медитаций с изображениями и длительностью сессии
- Логика блокировки premium-контента с возвратом на paywall для пользователей без подписки
- AI-flow с 3 вариантами настроения и выводом сгенерированной аффирмации
- Запрос к backend для генерации аффирмаций с безопасным локальным fallback
- Поддержка SafeArea на всех основных экранах

## Запуск через Docker

### Требования

- Docker
- Docker Compose

### Команды

Сначала создайте локальный `.env`:

```bash
npm run setup:env
```

Этот скрипт создаёт `.env`, если файла ещё нет, и пытается автоматически определить локальный IPv4-адрес хост-машины.

Поддерживаются такие сценарии:

- WSL: приоритетно используется Wi-Fi IP Windows-хоста через PowerShell
- Windows: используется конфигурация сети из PowerShell
- macOS: проверяются типичные Wi‑Fi-интерфейсы
- Linux: локальный source IP определяется по таблице маршрутизации

Если автоопределение сработало неверно, поправьте `.env` вручную и укажите Wi‑Fi IP хост-машины в `REACT_NATIVE_PACKAGER_HOSTNAME`.

Пример:

```env
REACT_NATIVE_PACKAGER_HOSTNAME=192.168.10.38
```

После этого:

```bash
docker compose build
docker compose up
```

Упрощённые команды:

```bash
make start
```

или

```bash
npm run docker:start
```

Опциональная полная пересборка:

```bash
docker compose down
docker compose build --no-cache
docker compose up
```

Также доступны:

```bash
make rebuild
make down
```

После запуска откройте проект в Expo Go, отсканировав QR-код из вывода Expo в терминале.

## Сценарий работы приложения

1. Приложение стартует на экране `Paywall`.
2. Пользователь выбирает один из трёх вариантов доступа:
   - `Free` → ограниченный доступ
   - `Monthly` → полный доступ
   - `Yearly` → полный доступ, визуально выделен как наиболее выгодный
3. Нижняя CTA-кнопка подтверждает выбор и открывает контент с медитациями.
4. На экране `Meditations`:
   - все пользователи видят полный список сессий
   - пользователи `Free` видят premium-сессии заблокированными
   - пользователи с premium-доступом могут открыть любую сессию
5. Нажатие на заблокированную медитацию без подписки возвращает пользователя на `Paywall`.
6. Кнопка `Go to AI Mood` открывает экран выбора настроения.
7. Пользователь выбирает одно из 3 настроений и генерирует аффирмацию.
8. Если backend недоступен, приложение возвращает реалистичную fallback-аффирмацию.

## AI-интеграция

Аффирмации запрашиваются у backend endpoint:

- `POST /api/affirmation`

Приложение отправляет выбранное настроение и ожидает текстовый ответ. Если запрос не удался или backend вернул некорректные данные, используется локальная fallback-аффирмация.

Связанный файл:

- [src/utils/mockLLM.ts](/home/asari/windsurf_projects/meditation-app/src/utils/mockLLM.ts)

## Особенности мобильного UX

- Используются `SafeAreaProvider` и `SafeAreaView`, чтобы заголовки и контент не пересекались с вырезами экрана и системным UI.
- Основные действия на всех экранах остаются крупными и удобными для нажатия.
- Карточки медитаций сохраняют консистентные отступы, размер изображений и оформление заблокированного состояния.
- Макет проверялся в web, в компактных phone-sized viewport и в Expo Go на реальном устройстве, чтобы избежать сломанных отступов и обрезанного контента.

## Где AI потребовал дополнительной ручной проверки

- Интерпретация paywall: итоговая версия использует карточку `Free` плюс два premium-тарифа, и это решение отдельно подтверждалось как допустимое
- Детали мобильного layout: отступы, иерархия карточек и акценты CTA требовали ручной проверки
- Web-специфичные предупреждения: устаревшие shadow-стили, interaction warnings и SafeArea deprecations пришлось чистить точечно
- Логика доступа к контенту: визуальное premium-состояние и поведение по нажатию потребовали ручной верификации

## Ответ на обязательный вопрос из README

Самые сложные для AI проблемы в мобильной вёрстке были связаны с адаптивными отступами, визуальной иерархией и стабильностью tap-target на разных размерах экрана. AI может быстро выдать визуально неплохой первый проход, но обычно недооценивает, насколько быстро layout ломается на маленьких экранах вроде iPhone SE: текст раньше переносится, кнопки начинают ощущаться тесными, карточки становятся слишком плотными, а вертикальные отступы, которые выглядят нормально на большом экране, на маленьком кажутся перегруженными.

Чтобы это контролировать, приложение пришлось вручную просмотреть экран за экраном и скорректировать:

- работу `SafeArea`, чтобы контент не попадал под системные зоны сверху и снизу
- отступы между карточками и общий ритм списка, чтобы экраны оставались читаемыми
- размеры кнопок и flow взаимодействия, чтобы основные действия оставались очевидными
- поведение заблокированных и незаблокированных медитаций, чтобы UI соответствовал бизнес-логике
- визуальную иерархию paywall, чтобы годовой тариф оставался самым заметным

На практике AI был особенно полезен для скорости и итераций, но финальное мобильное качество зависело от ручной проверки layout и interaction flow на маленьких и больших экранах.
